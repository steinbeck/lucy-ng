<facts>
<!-- Verified platform facts the doc must state (RESEARCH § PORT-02, Environment Availability). -->
- macOS Apple Silicon: native `mac11_arm64` NMRPipe build EXISTS — no Rosetta/VM needed for the
  CLI tools lucy-ng uses (nmrPipe/bruk2pipe/nusExpand.tcl). Only nmrDraw (GUI viewer, never invoked
  by lucy-ng) is documented as macOS-problematic. This dev machine (2026-07-18): arm64, macOS 26.5,
  csh+tcsh present, native (sysctl.proc_translated=0).
- SMILE ships as a SEPARATE companion download (`plugin.smile.tZ`, "Companion Files from the Ad Bax
  Group at the NIH"), NOT bundled with base NMRPipe. After only the base install,
  `nmrPipe -fn SMILE -help` reports "unknown function" and `lucy nus check` reports
  status "smile_plugin_missing" (RESEARCH Pitfall 2).
- Linux native: supported; historical 32-bit-lib caveat noted in milestone PITFALLS.md.
- Windows: NO native NMRPipe build since v8.9, and NO csh/tcsh — the generic PORT-01 checks
  (missing backend binary + missing csh) already fail correctly with no Windows-specific code
  (RESEARCH anti-pattern: do not special-case Windows). WSL2 is the documented workaround.
- Install source: https://www.ibbr.umd.edu/nmrpipe/install ; requires sourcing an
  `nmrInit.<platform>.com` environment script and adding `bin/` to PATH (registration-adjacent,
  edits .cshrc, may need a logout/login — a manual step, not automatable, per D-01).
- csh/tcsh is required as the shebang interpreter for bruk2pipe/nusExpand.tcl even though lucy-ng
  invokes them via direct subprocess.run (RESEARCH Pitfall 4).

Doc-shape analog (README lines ~237-260): `### <Tool>` heading + one-line description + link +
"Verify with: `lucy <group> check`" block — mirror this per platform row.
</facts>

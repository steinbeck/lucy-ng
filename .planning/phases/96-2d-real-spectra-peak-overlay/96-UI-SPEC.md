# Phase 96 — UI Design Contract: 2D Real Spectra + Peak Overlay

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is NOT a greenfield UI. It extends the shipped v9.2/9.3 webview
(vanilla JS + static HTML, no build tooling, no framework, no npm/shadcn — locked
project-wide constraint). All spacing, typography, and color tokens below are the
**existing, locked baseline** read directly from
`src/lucy_ng/webview/static/index.html`'s inline `<style>` block and from the shipped
`src/lucy_ng/webview/routers/spectra.py` (Phase 95) — documented here for
traceability, not re-invented. The only genuinely new visual surface this phase
introduces is the **server-rendered matplotlib contour PNG** (HSQC/HMBC/COSY + overlay
+ placeholder states) and three new `<img>` mounts replacing the
`data-panel="spectra-2d"` placeholder. Tab bar, panel box model, section/heading
classes, `.spectrum-img` styling, and the whole-tab layout skeleton are reused verbatim
from Phase 93/94/95 — no new CSS class beyond what Phase 95 already shipped is needed
for the frontend shell.

Every visual/interaction decision this phase needs is already locked by
`96-CONTEXT.md` (D-01 through D-10) and `96-RESEARCH.md`'s verified rendering
prototype. This document translates those locked decisions into the exact
copy/color/typography/layout contract the planner and executor need — it does not
introduce new discretion beyond what CONTEXT.md explicitly delegated (figure sizing,
exact wording of "unavailable" states, and whether an in-chart flag legend is added).

## Copywriting Contract

Mirrors Phase 95's exact wording style and state taxonomy (SP-02), extended to three
independent plots. Each of the three routes (`/api/spectra/2d/hsqc`,
`/api/spectra/2d/hmbc`, `/api/spectra/2d/cosy`) renders its OWN placeholder
independently (D-10) — the messages below are per-plot, substituting the experiment
name.

| Element | Copy |
|---------|------|
| Primary CTA | N/A — read-only image tab, no buttons or actions in this phase |
| Tab section heading (HSQC) | `HSQC` (reuses `.tables-heading`, matches the Tables-tab `HSQC` heading exactly — Phase 94 precedent) |
| Tab section heading (HMBC) | `HMBC` |
| Tab section heading (COSY) | `COSY` |
| Empty state — no manifest at all (D-01/D-05, inherited from Phase 95) | In-chart placeholder text: `"Waiting for a live CASE run — spectra will appear once analysis starts."` (identical wording to Phase 95 — same underlying cause) |
| Empty state — manifest present, `bruker_data_dir` stale/unreadable (D-05, inherited) | In-chart placeholder text: `"Raw Bruker data not found at the recorded path."` (identical wording to Phase 95) |
| Empty state — no matching HSQC experiment found | In-chart placeholder text: `"No HSQC experiment found in this dataset."` |
| Empty state — no matching HMBC experiment found | In-chart placeholder text: `"No HMBC experiment found in this dataset."` |
| Empty state — no matching COSY experiment found | In-chart placeholder text: `"No COSY experiment found in this dataset."` |
| Partial state — contour renders but the corresponding peaks JSON (`hsqc.json`/`hmbc.json`/`cosy.json`) is missing/malformed (SP-02) | Real contour renders normally; small in-chart annotation top-right: `"peak positions unavailable"` (identical wording to Phase 95 — does NOT replace the whole chart, the contour itself is still valid QC data) |
| Error state | Not applicable — SP-02 mandates HTTP 200 + a placeholder chart for every failure mode; no user-facing error/500 path to word |
| Destructive confirmation | Not applicable — no destructive actions in this phase (read-only dashboard) |

**Wording rule (explicit, since three near-identical messages are easy to drift):**
the three "no matching experiment found" messages differ ONLY in the experiment-type
noun (`HSQC`/`HMBC`/`COSY`) — do not otherwise reword between routes. All three are
treated as the defensive/rare case (like Phase 95's "no ¹³C experiment found"), not
as an expected/common case (unlike Phase 95's "no ¹H experiment" wording) — a real
CASE run always acquires HSQC+HMBC+COSY as part of the standard experiment set, so a
genuinely missing one is noteworthy, not routine.

## Layout & Interaction Contract (extends Phase 95's addendum to the template)

**DOM structure** (replaces the Phase 93/95 placeholder inside
`[data-panel="spectra-2d"]`, currently `<div class="placeholder"
data-panel="spectra-2d">2D Spectra — coming in Phase 96</div>` at `index.html` line
~435):

```html
<div data-panel="spectra-2d">
  <section class="tables-section" id="spectrum-hsqc">
    <h2 class="tables-heading">HSQC</h2>
    <img id="img-spectrum-hsqc" class="spectrum-img"
         alt="HSQC contour plot with cross-peak overlay"
         src="/api/spectra/2d/hsqc">
  </section>
  <section class="tables-section" id="spectrum-hmbc">
    <h2 class="tables-heading">HMBC</h2>
    <img id="img-spectrum-hmbc" class="spectrum-img"
         alt="HMBC contour plot with cross-peak overlay, colour-coded by flag"
         src="/api/spectra/2d/hmbc">
  </section>
  <section class="tables-section" id="spectrum-cosy">
    <h2 class="tables-heading">COSY</h2>
    <img id="img-spectrum-cosy" class="spectrum-img"
         alt="COSY contour plot with cross-peak overlay and diagonal"
         src="/api/spectra/2d/cosy">
  </section>
</div>
```

**No new CSS class needed.** `.spectrum-img` (shipped by Phase 95, `index.html`
~line 372: `width:100%; height:auto; display:block; background:#fff; border:1px solid
#dee2e6; border-radius:6px;`) is reused verbatim for all three `<img>` elements — D-09
requires "stacked vertically, all rendered," which `.tables-section`'s existing
`display: block` + `margin-bottom: 16px` box model already produces with zero new
styling.

**Endpoint shape (LOCKED by D-10 — three independent routes):**
`/api/spectra/2d/hsqc`, `/api/spectra/2d/hmbc`, `/api/spectra/2d/cosy` — mirrors
Phase 95's `/api/spectra/1d/{carbon,proton}` split exactly, so each plot degrades to
"unavailable" independently.

**Poll/refresh behaviour** (mirrors Phase 95's `refreshSpectra1D` shape exactly — no
SMILES-diffing/dedupe, since D-04's mtime-keyed server-side cache is what avoids
redundant *rendering* work; the frontend still cache-busts the browser's `<img>`
network request every poll, same division of responsibility as Phase 95):

```js
function refreshSpectra2D() {
  var t = Date.now();
  var h = document.getElementById('img-spectrum-hsqc');
  if (h) { h.src = '/api/spectra/2d/hsqc?t=' + t; }
  var m = document.getElementById('img-spectrum-hmbc');
  if (m) { m.src = '/api/spectra/2d/hmbc?t=' + t; }
  var c = document.getElementById('img-spectrum-cosy');
  if (c) { c.src = '/api/spectra/2d/cosy?t=' + t; }
}
```

Add `refreshSpectra2D();` to `tick()` alongside the existing `refreshSpectra1D()` /
`refreshCarbon()` / etc. calls. No `fetch().then(json)` parsing needed — same
`<img>`-native binary-payload pattern as Phase 95 and `structures.py`.

**Figure sizing/DPI (matplotlib — applies to both the real-contour and
placeholder-chart render paths for all three routes, so layout never jumps between
states):**

| Property | Value | Rationale |
|---|---|---|
| `figsize` | `(9.0, 6.0)` inches | Taller than Phase 95's 1D `(9.0, 3.0)` to give the F1/y-axis room for a contour plot; same 9.0" width for visual column alignment with the 1D tab and the stacked layout (RESEARCH.md Pattern verified prototype value) |
| `dpi` | `100` (→ 900×600 px raster, scales down responsively via `.spectrum-img { width:100% }`) | Matches Phase 95's DPI exactly |
| Contour line width | `0.5` pt | RESEARCH.md verified prototype value; thin enough that ~8 geometric levels don't visually merge |
| Cross-peak marker | open circle, `s=30` (matplotlib scatter size units), `linewidths=1.0`, `facecolors="none"` | RESEARCH.md verified prototype value (Pattern 6) — visible ring, contour stays visible through the center |
| COSY diagonal line width | `0.5` pt, solid | Matches contour line weight so it reads as a subtle guide, not a data feature |
| Margins | matplotlib default `tight_layout()` / `constrained_layout=True` | Matches Phase 95 — no manual margin tuning |

**Contour level construction (LOCKED shape by D-01, exact constants are this
document's binding record per CONTEXT.md's "document the chosen values" requirement):**

| Parameter | Value | Source |
|---|---|---|
| Noise floor | `5.0 × sigma` where `sigma = _compute_2d_noise_sigma(full-resolution data)` | RESEARCH.md Pattern 4 — reuses the existing `snr_floor=5.0` convention from `PeakPicker2D.pick_peaks`, imported (not re-derived) from `peak_picker_2d.py` |
| Growth factor | `1.4` (geometric) | RESEARCH.md verified prototype — produced a visually-graduated ladder for HSQC/HMBC/COSY in the timed test run |
| Level count | `8` | D-01 target ("~8 levels") |
| Sign | positive-only | D-03 — locked |
| Computed on | full-resolution data, BEFORE decimation | RESEARCH.md Pitfall 2 — decimating first biases MAD upward and can hide real weak HMBC cross-peaks |

**Decimation (LOCKED method preference by D-04):** block-maximum (max-pooling) to
≤512×512, ceiling-division block size, edge-padded if the source dimension does not
evenly divide the target — the numpy `reshape(...).max(axis=(1,3))` pattern verified
in RESEARCH.md Pattern 3 (7ms for 1024×2048→512×512). Striding (`data[::step]`) is
acceptable ONLY as a documented fallback if block-max cannot meet the <1s budget —
not expected to be needed per the verified 0.10-0.13s end-to-end timing.

**Axis labels per plot type (through the shared `_apply_nmr_axes_2d` helper, D-08):**

| Plot | x-axis label | y-axis label | x data | y data |
|---|---|---|---|---|
| HSQC | `δH (ppm)` | `δC (ppm)` | `f2_ppm_scale` / `proton_ppm` overlay | `f1_ppm_scale` / `carbon_ppm` overlay |
| HMBC | `δH (ppm)` | `δC (ppm)` | same as HSQC | same as HSQC |
| COSY | `δH (ppm)` | `δH (ppm)` | `f2_ppm_scale` / `proton_a_ppm` overlay | `f1_ppm_scale` / `proton_b_ppm` overlay |

Both axes reversed on all three plots (`ax.set_xlim(scale[0], scale[-1])` with
already-descending Bruker scales — no `[::-1]`, per RESEARCH.md Pattern 2's
empirical verification). Concrete acceptance check (mirrors ROADMAP SC1):
`ax.get_xlim()[0] > ax.get_xlim()[1]` AND `ax.get_ylim()[0] > ax.get_ylim()[1]` on
all three plots.

**HMBC in-chart flag legend (NEW discretionary decision — not explicitly required by
CONTEXT.md, added here because the Tables tab conveys flag meaning via a text
column that the 2D plot has no equivalent of):** draw a compact 3-line text legend in
the HMBC plot's top-right corner, one line per flag, 7pt, coloured in that flag's
hex, reusing the exact same corner slot convention as the "peaks unavailable"
annotation (never both drawn simultaneously — the legend only appears when peaks
render successfully):

```
ok
potential_4J
1J_artifact
```

Each line coloured `#28a745` / `#ffc107` / `#adb5bd` respectively, right-aligned,
stacked with normal line spacing, no background box (keeps the "calm background"
goal from D-02 — the legend is text, not a filled swatch). This is the ONLY new
visual element beyond what CONTEXT.md's decisions strictly require; it exists purely
so the flag-colour meaning is self-contained within the 2D tab, matching the "avoid
new interaction pattern" spirit of D-09 (no cross-tab lookup required to read the
plot). HSQC and COSY plots do not get a legend (their markers are uniform/single
colour — nothing to key).

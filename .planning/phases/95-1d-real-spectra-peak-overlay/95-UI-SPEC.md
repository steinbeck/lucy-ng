# Phase 95 — UI Design Contract: 1D Real Spectra + Peak Overlay

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is NOT a greenfield UI. It extends the shipped v9.2/9.3 webview
(vanilla JS + static HTML, no build tooling, no framework, no npm/shadcn — this is a
locked project-wide constraint, see REQUIREMENTS.md "Out of Scope"). All spacing,
typography, and color tokens below are the **existing, locked baseline** read directly
from `src/lucy_ng/webview/static/index.html`'s inline `<style>` block — they are
documented here for traceability, not re-invented. The only genuinely new visual
surface this phase introduces is the **server-rendered matplotlib PNG chart**
(trace + peak overlay + placeholder states) and the two `<img>` mounts in the existing
"1D Spectra" tab. Everything else (tab bar, panel box model, section/heading classes)
is reused verbatim from Phase 93/94.

## Spacing Scale

The existing webview does not use a pure 8-point scale; it uses a handful of
sub-8 values (4/6/10) alongside 8/12/16/24/32. These are the **existing, locked**
values — do not introduce new ones for this phase.

| Token | Value | Usage (existing) |
|-------|-------|-------------------|
| xxs | 4px | Badge padding, icon-scale gaps, table cell inline padding |
| xs | 6px | Panel/tile border-radius (`.tile`, `[data-panel]`) |
| sm | 8px | Compact gaps (`#main` gap secondary axis, table cell vertical padding, tab-bar gap fallback) |
| sm+ | 10px | `#structure-grid` gap (pre-existing exception, not introduced by this phase) |
| md | 12px | `#main` padding/gap, panel padding, border-radius on tiles |
| lg | 16px | Status-bar padding, default section margins, tab-bar button horizontal padding |
| xl | 24px | `.tables-subsection` top margin |
| — | 32/48/64 | Not currently used anywhere in the webview; not needed by this phase |

**Exceptions for this phase (new):**
- `.spectrum-img` (new class, see Copywriting/Layout below) reuses the existing
  `6px` border-radius and `#dee2e6` 1px border tokens from `.tile`/`[data-panel]`
  — no new spacing values introduced.
- Vertical gap between the ¹³C and ¹H spectrum sections: reuse the existing
  `.tables-section { margin-bottom: 16px; }` rule verbatim (already present,
  applies automatically if the same class is reused — see Layout below).

No new CSS typography tokens are introduced. The ¹³C/¹H section headings in the
1D Spectra tab reuse `.tables-heading` (14px/600) exactly as Phase 94's Tables tab
sections do.

**Chart-internal typography (NEW — matplotlib text, specified in points at 100 DPI,
since CSS rules do not apply inside a rasterized PNG):**

| Chart element | Font size (pt) | Weight | Color | Notes |
|---|---|---|---|---|
| Axis label (`δ (ppm)`) | 9 | normal | `#495057` | matches CSS secondary-text color |
| Tick labels | 8 | normal | `#495057` | matplotlib default tick styling otherwise |
| Peak ppm label | 7 | normal | `#0c5460` (accent — see Color) | rotated 90°, anchored just above each marker tick |
| Peak assignment label (when present) | 7 | normal | `#0c5460` | placed above the ppm label, only drawn when `assignment` is non-empty in the JSON |
| In-chart "peaks unavailable" note | 7 | italic | `#6c757d` | top-right corner annotation, drawn only when peak JSON is missing/malformed but the raw trace still rendered (SP-02 partial-degradation case) |
| Placeholder / unavailable message | 11 | normal | `#6c757d` | centered in an axis-off figure — mirrors `.table-waiting` CSS styling (12px italic grey) scaled to chart-point equivalent |

## Color

Existing 60/30/10 CSS palette (locked baseline, unchanged by this phase):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8f9fa` (page bg) / `#ffffff` (panel/card bg) | Page background, panel/tile/table surfaces, chart figure background |
| Secondary (30%) | `#495057` / `#6c757d` / `#dee2e6` (borders) | Headings, captions, borders, secondary/disabled text |
| Accent (10%) | `#0c5460` | **Reserved for:** focus-visible outline (existing), `badge-running` text, and — **new this phase** — the peak-overlay markers, ppm labels, and assignment labels on the 1D spectrum chart. Never used for the trace line itself. |
| Destructive | `#721c24` on `#f8d7da` (`badge-error`) | Existing error badge only; **not used** in this phase — the "unavailable/waiting" states use the neutral grey (`#6c757d`), not the destructive/error palette, because a missing spectrum during a live run is an expected transient state, not an error |

**Chart-specific color assignments (NEW — must respect the palette above, not invent new hues):**

| Chart element | Color | Rationale |
|---|---|---|
| Trace line | `#495057` (secondary) | Neutral, so the accent color is reserved exclusively for peak overlay per the 10%-accent rule |
| Peak marker (vertical tick) | `#0c5460` (accent), 0.75pt line width, drawn to ~70% of axis height | Thin, subtle, matches D-03's "subtle colour that respects v9.2/9.3 visual language" |
| Peak ppm/assignment labels | `#0c5460` (accent) | Same accent family as the marker — keeps the overlay visually as one cohesive "accent" element |
| Placeholder/unavailable text | `#6c757d` (secondary/grey) | Matches `.table-waiting` convention exactly |
| "Peaks unavailable" in-chart annotation | `#6c757d` (secondary/grey) | Same neutral as above — a note, not an error |
| Figure/axes background | `#ffffff` | Matches panel surface color (dominant) |
| Axis spines/gridlines | `#dee2e6` (existing border color) or matplotlib default light grey — no bold gridlines | Consistency with table border color; keep chart uncluttered |

## Layout & Interaction Contract (NEW this phase — narrow addendum to the template)

This section captures the frontend wiring decisions needed by the planner/executor,
since the "component" here is a PNG-in-an-`<img>`, not a conventional widget.

**DOM structure** (replaces the Phase 93 placeholder inside `[data-panel="spectra-1d"]`):

```html
<div data-panel="spectra-1d">
  <section class="tables-section" id="spectrum-carbon">
    <h2 class="tables-heading">&sup1;&sup3;C Spectrum</h2>
    <img id="img-spectrum-carbon" class="spectrum-img"
         alt="13C 1D spectrum with peak overlay"
         src="/api/spectra/1d/carbon">
  </section>
  <section class="tables-section" id="spectrum-proton">
    <h2 class="tables-heading">&sup1;H Spectrum</h2>
    <img id="img-spectrum-proton" class="spectrum-img"
         alt="1H 1D spectrum with peak overlay"
         src="/api/spectra/1d/proton">
  </section>
</div>
```

**New CSS class** (add to the existing `<style>` block, reusing existing tokens only):

```css
.spectrum-img {
  width: 100%;
  height: auto;
  display: block;
  background: #fff;
  border: 1px solid #dee2e6;
  border-radius: 6px;
}
```

**Endpoint shape (resolves CONTEXT.md's "Claude's Discretion" — two separate routes):**
`/api/spectra/1d/carbon` and `/api/spectra/1d/proton` — two independent PNG routes,
each independently capable of returning its own "unavailable" placeholder (satisfies
the discretion note "per-nucleus unavailable must be independently expressible").
Both sections are always present in the DOM (never conditionally removed) — absence
of a ¹H experiment is communicated by the placeholder chart inside the `<img>`, not
by hiding the `#spectrum-proton` section. This keeps the frontend logic identical to
Phase 94's pattern (always render the container; vary only the content).

**Poll/refresh behaviour:** Per D-06 (no render caching in Phase 95 — cheap to
re-render), do NOT reuse the SMILES-diffing pattern from `structures.py`
(`lastSmiles` dedupe). Simply cache-bust both `<img>` sources on every ~3s tick:

```js
function refreshSpectra1D() {
  var t = Date.now();
  var c = document.getElementById('img-spectrum-carbon');
  if (c) { c.src = '/api/spectra/1d/carbon?t=' + t; }
  var p = document.getElementById('img-spectrum-proton');
  if (p) { p.src = '/api/spectra/1d/proton?t=' + t; }
}
```

Add `refreshSpectra1D();` to `tick()` alongside the existing `refreshCarbon()` /
`refreshHsqc()` / etc. calls. No `fetch().then(json)` parsing is needed for this
tab — the browser's own `<img>` loading handles the binary payload directly (mirrors
the `img2.src = '/api/structure/' + idx + '.svg?t=' + Date.now();` pattern already
used in `webview.js` for structures, minus the SMILES-diff optimization since D-06
explicitly says the extra render cost is acceptable here).

**Figure sizing/DPI (matplotlib, applies to both real-chart and placeholder-chart
render paths — must match so the layout does not jump between states):**

| Property | Value |
|---|---|
| `figsize` | `(9, 3)` inches |
| `dpi` | `100` (→ 900×300 px raster, scales down responsively via `.spectrum-img { width: 100% }`) |
| Trace line width | `1.0` pt |
| Peak marker line width | `0.75` pt, height ≈ 70% of axis y-range (from x-axis upward) |
| Margins | matplotlib default `tight_layout()` / `constrained_layout=True` — no manual margin tuning needed |

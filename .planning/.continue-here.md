## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Symptom-to-cause invention | Twice this session I saw a symptom, invented a cause, and acted on it before reading the code that produces the symptom. (1) `Execution error` in a run log → declared CLI 2.1.224 broken, killed a healthy run, committed a false claim. It is what `claude -p` prints when `timeout` kills it. (2) empty `top_smiles` in `meta.json` → declared the grader broken. That field comes from a crude grep in `blind_case_run.sh`; the grader has its own RDKit-validated extractor and works fine. | blocking | Before asserting a cause, locate and read the code that emits the symptom. State which file and line produces it. If you cannot, you do not have a cause — you have a guess. |
| Grading against an unverified reference | `NUS-RECONSTRUCTION-GUIDE.md` §8/§10 was cited as "ground truth" across three phases, in two source modules and the roadmap. It is a prior CASE agent's hypothesis, written into the output directory of a failed run, about an unsolved sample. Phase 103's headline "17/20 matched" is therefore circular. | blocking | Verify the provenance of any reference at the point it is first cited — who produced it, from what, when. An artefact sitting in a run's own output directory is a suspect, not a source. |
| Diagnosing long runs by elapsed time or log lines | A CASE run takes 1.5–2.5 h and hits the 3600 s call timeout once per attempt, by design (resume-backstop). Judging "stuck" from a log line cost a working run and ~15 probe calls of the user's quota. | advisory | Judge progress by artefacts appearing in `analysis/` (iteration dirs, `timing.jsonl`), never by log text or elapsed time. |

## Critical Anti-Patterns

Carried forward from the 2026-08-08 handoff (still true, all discovered through real
failure), plus three found this session.

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| **A broken measurement setup returns a plausible number, not an error** | Three times this session. (1) `ControlPath` over the 104-byte Unix-socket limit → eight ssh calls failed and the timing loop printed `0 ms`, which reads as "blazing fast". (2) An empty PID list reached `ps -p`, which then silently summed **all 969 processes** on the host — reported as "149 % CPU, 24 GB" for 38 webview servers. (3) `pgrep -f "lucy-ng:case"` found nothing on a host where two runs were healthily in progress, because resumed runs carry `--resume … -p Continue the in-progress CASE workflow` instead. | blocking | Every measurement needs a positive control: prove the setup reports the expected value in a case where the answer is known, before trusting it where it is not. A suspiciously clean number (0 ms, exactly 100 %, a round total) is a failure signal, not a result. |
| **Tests that spawn real processes** | The first revision of the opt-out tests called `serve` without patching `server.start`, leaving **eight live uvicorn servers** on the dev machine — while the feature under test existed to stop exactly that leak. | blocking | Patch the side-effecting entry point in a fixture shared by every test in the class, so no test can start a real server regardless of implementation state. Runtime is the tell: 4.35 s → 0.40 s once nothing spawned. |
| **Reading a stale planning doc as current fact** | `STATE.md` was reported to the user verbatim, including "CR-02/CR-03 filed, not fixed". Both had been fixed on 2026-08-03 in `7dfe2ce`. The file's own header date was wrong too. | blocking | Before citing a planning document as the current state, check it against git: `git log --since=<doc date>` for the paths it describes. The doc is a snapshot with a date, not a source of truth. |
| **Framing a settled decision as an open defect** | The benchmark's mixed provenance (two skill states, two team models) was written up as a to-do proposing re-runs. It was in fact a deliberate, discussed decision on cost grounds. | advisory | Before filing something as a defect, ask whether it was chosen. A trade-off someone accepted belongs in the decision record with its rationale, not in a to-do list that reopens it. |
| **Symptom-to-cause invention** (from 2026-08-08) | `Execution error` in a run log → declared the CLI broken, killed a healthy run, committed a false claim. It is what `claude -p` prints when `timeout` kills it. | blocking | Locate and read the code that emits the symptom before asserting a cause. Name the file and line. Without that you have a guess, not a cause. |
| **Grading against an unverified reference** (from 2026-08-08) | `NUS-RECONSTRUCTION-GUIDE.md` §8/§10 was cited as "ground truth" across three phases and two source modules. It is a prior agent's hypothesis about an unsolved sample, written into a failed run's own output directory. | blocking | Verify a reference's provenance where it is first cited — who produced it, from what, when. An artefact sitting in a run's own output directory is a suspect, not a source. |
| **Diagnosing long runs by elapsed time or log lines** (from 2026-08-08) | A CASE run takes 1.5–2.5 h and hits the 3600 s call timeout once per attempt by design. | advisory | Judge progress by artefacts appearing in `analysis/` (iteration dirs, `timing.jsonl`), never by log text or elapsed time. |

<decisions_made>

- **Opt-out lives in `lucy webview serve`, not in `case.md`.** `case.md` is byte-frozen with a
  committed SHA-256 guard, and its launch block explicitly forbids extra arguments — so an
  environment variable is the only switch that reaches through the frozen call. A CLI flag
  would have been useless here. `case.md` verified byte-unchanged via git.
- **Only `1`/`true`/`yes`/`on` disable.** `0`/`false`/`no`/empty keep the dashboard, so setting
  the variable to a negative value can never silently cost someone their dashboard.
- **The opt-out is checked before `_require_webview()`** — doing nothing needs no dependency,
  so a disabled run also succeeds where the `[webview]` extra is absent.
- **Interactive runs keep their post-run dashboard.** `case.md` leaves it up on purpose
  (WV-07, line 945); only headless benchmark runs were leaking.
- **The benchmark's mixed provenance is an accepted decision, not a defect.** Runs span two
  skill states *and* two team models (4.8 → Opus 5 via `f9aa7b3`). Keeping them was chosen on
  cost grounds. The obligation is to state the mixed provenance beside every number — never a
